# 靶场试玩：每局导出一份 CSV

1. 选枪；第一份基线建议 **Vandal → 消灭 50 → 机器人护甲关**。射击场景面板上的「开始」，正常玩。自由练习不计入挑战。
2. 结束后按 **`~` → 靶场设置 → 本地试玩数据**，选中对应场次（默认最新）。需要按人配对时，给同一位玩家填写相同的编号，例如 `P01`。
3. 点 **「导出所选局 CSV」**，文件在浏览器下载目录。把原文件发给分析者即可。消灭与速度挑战均支持；玩到一半也可以先点「取消本局」再导出。

每份 CSV 只含一局，使用 UTF-8 BOM、逗号分栏，Excel 可直接打开。当前关卡内存保留最近 10 个已结束的挑战；可以重复下载，刷新或离开关卡前请先保存。数据不上传服务器。

### 先看最后一行 `run_end`

| 指标 | 计算口径 |
|---|---|
| `kpm` | `60000 × kills / active_ms`。实际击杀含最终一枪的全部有效致死；`score_kills` 为游戏计分（消灭模式在达标数封顶）。 |
| `head_kill_rate` 爆头率 | `head_kills / kills`，枪械头部致死占所有击杀的比例；身体补枪不算头杀。分析单枪可以用 `weapon` 过滤 `kill`。 |
| `miss_rate` 打空率 | `misses / shots`。每次真正射出的枪次作一个样本；墙壁、空气都是打空；部分弹丸打到机器人算命中。近战、空扣扳机、开始挑战的交互枪不进分母。 |

分母为零时指标留空。`reason=completed` 表示正常完成；其他原因标记取消、重生等中断，不要混成完赛局。`dropped_rows>0` 表示超出单局 20,000 条明细保护线，终局计数仍完整，不宜用这局重建逐发序列。

### 要复盘时再看事件行

| 字段 / 事件 | 含义 |
|---|---|
| `run_id`、`player_id`、`started_utc` | 一局的随机 ID、选填的玩家代号和 UTC 开始时间；重复下载按 `run_id` 去重。`input_layout` 是运行时使用的键鼠/触控布局，不是硬件鉴定。 |
| `schema`、`rules_version`、`damage_version`、`mode`、`difficulty`、`goal`、`armor`、`ammo_policy` | CSV 格式、玩法与伤害配置版本、本局条件；消灭模式的速度难度不适用，留空。 |
| `run_start`、`pause`、`resume`、`run_end` | `wall_ms` 为相对开局的真实毫秒，`active_ms` 扣除引擎暂停；仅打开设置、游戏仍运行时照计。`sim_ms` 是规则固定时钟（视野事件用呈现时钟），掉帧时可不同于真实耗时。 |
| `spawn`、`first_in_view`、`expire` | 通过 `spawn_id` 串起同一条命；`cell_id` 与 `x/y/z` 记录出生点。`first_in_view` 是模型进入呈现状态后，头/胸参考点首次落入相机视锥且至镜头未被房间碰撞盒挡住的采样帧；不是玩家注视时间，也不保证像素无遮挡。视野外已死亡/过期可没有此行。 |
| `shot` / `melee`、`damage`、`kill` | `shot_id` 把一次攻击连到零至多条实际伤害、致死；`weapon` 是当时武器，`magazine_after` 为射后匣内余弹。`hit=1/0` 记在攻击行；每条 `damage` 单列部位、扣血/甲；每条 `kill` 只对应一个有效 `spawn_id` 和致死部位。 |
