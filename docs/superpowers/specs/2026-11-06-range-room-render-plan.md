# 练枪房渲染接入与升级计划 · V3

日期：2026-11-06。状态：首版已实现，资源、材质隔离及 WebGPU 管线已通过自动验证；最终灯光观感与目标帧率仍需按测试设备验收。实施证据见 [V3 实施与验证记录](../../lighting/range-room-v3-implementation.md)。

**本文是当前唯一的渲染实施基线，替代此前整图、纯光照 lightmap 和多区域探针路线。** 历史实验保留供查阅，不再自动继承其中的资产、对象数量、坐标偏移或性能结论。

**同日用户追加要求**：Reinhard、曝光强度 **1.2（非 EV）**、日间天空、走廊顶棚点光、AO/LUT 调试面板；随后明确未烘焙物件属于 Minecraft 像素风，必须使用最近邻而不是线性插值。以第 12 节及更新后的采样/显示规则为准，不重烘、不改 UV。

## 1. 已确认的制作成果与本轮目标

### 1.1 用户确认的最新范围

- 场景已缩减为一个练枪房，玩家只在房间内活动。
- 墙体 geometry 已完成 UV 展开，并按材质组织烘焙；部分占用较少的内容共用 atlas。
- 已有 **5 张 atlas**，本轮复用已经完成的降噪结果，不重新设计 UV 或重新烘焙。
- 房间内其余物体未烘焙，需要运行时照明，并加入 GTAO 补充接触遮蔽。
- 室内实时灯以 Blender 的三排线型顶灯为主要参考。

“墙体”是用户描述的已烘焙主体，不据此猜测地面、地毯或其他 mesh 的归属。最终逐 primitive 列出已烘焙和未烘焙接收面，以导出清单为准。集合成员或材质名称不作为自动分类的唯一依据。

本轮目标：先在 Three.js 中准确还原已有烘焙外观，再让未烘焙物体获得方向正确、亮度协调的室内实时照明与 GTAO，最后验收抗锯齿和性能。

## 2. 总体渲染分工

```text
已烘焙接收面：BakeUV → 对应降噪 atlas → 不重复受光的烘焙显示材质
未烘焙物体：原始纹理/PBR材质 → 顶灯实时直射 + 受控环境补光
                                                ↓
                                   GTAO 调制间接光分量

两类几何共同提供有效深度/法线 → HDR 场景输出 → 显示变换 → 抗锯齿
```

| 对象类别 | 接收实时顶灯 | 作为 GTAO 遮挡者 | 接收 GTAO | 动态阴影 |
|---|---|---|---|---|
| 已烘焙墙体等接收面 | 否 | 是 | 默认否 | Spot 方案中可作为投影遮挡者；不默认接收新阴影 |
| 未烘焙静态物件 | 是 | 是 | 是，主要作用于间接光 | 采用有阴影灯方案后逐类设置 |
| 角色、武器、可移动物件（若存在） | 是 | 是 | 是，需支持变形/动画 | 按可读性与性能需要验收 |
| 顶灯可见发光面 | 自发光外观 | 按实际几何 | 不默认压暗发光部分 | 不把发光材质当作实时光源 |

接收实时灯和接收 AO 由材质路径明确控制；不能把 `camera.layers` 当作逐物体的灯光链接系统。两个类别共享源材质时，先克隆或拆分运行时材质，避免修改一个对象而影响另一个类别。

## 3. 资产导出与绑定协议

### 3.1 保留制作成果

1. 仅导出当前房间所需几何、原始纹理、必要灯具外观和参考相机；范围由显式对象清单决定。
2. 保留原始颜色 UV 和烘焙 UV；不重新 unwrap、打包或自动合并几何。
3. 不直接依赖 Blender 的“相机射线 → 混合着色器”经 glTF 自动还原。导出模型后，由运行时显式绑定烘焙显示材质。
4. 保留原始 `.blend` 与烘焙数据。若需导出专用简化材质，在副本或可恢复的导出流程中处理，不覆盖用户源材质。
5. 多对象共用一页、单对象不同材质面使用不同页都必须支持。5 页 atlas 不等于 5 个物体、5 个 draw calls 或 5 个空间区域。
6. 为导出接收面建立稳定 ID，并记录 glTF mesh/primitive 对应关系。加载器拆分多材质 mesh 后仍能准确绑定，不能仅依赖显示名称、材质后缀或数组遍历顺序。

### 3.2 拟定运行时资源路径

```text
public/model/range-room.glb
public/lighting/range-room/manifest.json
public/lighting/range-room/atlases/B01.exr
public/lighting/range-room/atlases/B02.exr
public/lighting/range-room/atlases/B03.exr
public/lighting/range-room/atlases/B04.exr
public/lighting/range-room/atlases/B05.exr
```

这些是新版本约定，不代表文件已存在。正式文件名与绑定可在首次导出时固化；旧 `map.glb`、`map_lightmap.glb` 和历史实验资源不覆盖、不删除，也不作为缺失资源的静默替代。

首版优先导出五张经过确认的、统一为场景线性 RGB 的 HDR EXR，保留已完成的降噪结果。这里只统一输出编码，不重算光照。原图与降噪图无需同时加载到游戏中。

### 3.3 Manifest 必须记录的内容

| 字段组 | 必需信息 |
|---|---|
| 版本 | schema、房间模型版本、烘焙版本、模型及 atlas 内容 hash |
| 坐标 | Blender 到 glTF/Three.js 的转换、单位、模型根变换 |
| Atlas | 稳定页 ID、URL、尺寸、实际编码/色彩空间、内容类型、采样与 mip 策略 |
| 绑定 | 接收面稳定 ID、glTF mesh/primitive、atlas ID、UV 通道、必要的 UV 变换 |
| 分类 | `baked-appearance` / `realtime` / `fixture-emissive`，以及 AO、阴影策略 |
| 灯光 | Blender 原始参数、运行时灯类型与校准参数、作用对象类别 |
| 显示 | 参考曝光、显示变换、是否已把显示变换写入图片 |
| 验收 | 导出对象统计、参考相机、缺失绑定、UV 和色彩检查结果 |

导出和加载必须同时验证：每个已烘焙接收面只有一个有效绑定，引用页存在，UV 通道存在，模型与 atlas 来自同一版本。未知类别、重复绑定或缺页直接报错，不默认为实时材质或黑色贴图。

## 4. 成品烘焙图的材质与颜色约定

### 4.1 本版采用 baked appearance，不采用纯 GI lightmap

现有节点把降噪 atlas 作为自发光颜色显示。本版据此以“已包含底色与烘焙照明的成品外观”接入，导出时核对实际内容，不因名称含 HDR 或 lightmap 就推断其语义。

- 使用不重复受光的节点材质，例如以 `MeshBasicNodeMaterial` 显式采样烘焙 UV。
- **不把成品 atlas 直接赋给 `material.lightMap`，不再乘原始底色，也不沿用纯 irradiance 的去 albedo / π 换算。**
- 已烘焙外观不再接收同一组静态顶灯、环境漫反射或 GTAO。
- “不受光”不等于“不做显示变换”。若输入为场景线性 HDR，仍与其他物体一起经过统一曝光、tone mapping 与输出颜色转换。
- 原始纹理和源材质留作未烘焙物件、制作与后续修改使用，不要求在运行时重建整套 Blender 节点。

### 4.2 色彩管理是首次接入的验收项

当前检查到 Blender 使用 **AgX、曝光 −0.5 EV、Look None、Gamma 1**。此前 B01 降噪图的色彩空间/路径与 B02–B05 不一致，导出时必须重新核对实际像素编码，不能仅按扩展名或图像名称批量改标签。

规范：

- 五张正式运行时 atlas 统一为场景线性 Rec.709/sRGB 原色，HDR 数值保留；不要把 AgX、曝光或 LUT 烘进这一路径。
- EXR 按线性颜色加载，不走默认 sRGB 的普通颜色纹理加载设置。
- sRGB 编码 PNG 的传递函数与“已经经过 AgX 的显示成片”是两回事。若发现某页已包含显示变换，先定位正确源图，不能简单改成线性色彩空间来修复。
- 不因 EXR 是线性颜色就跳过最终显示变换，也不能在材质、renderer 和后处理上重复执行。
- 先用线性采样值和灰色测试物件排查资源错误，再比较最终截图。Three.js 的 AgX 可作为显示基线候选，但不能宣称与 Blender OCIO AgX 完全一致。
- 原计划的 Neutral tone mapping 不再作为未经比较的强制选择；显示方案在本轮画面对齐后记录为固定配置。

### 4.3 UV、滤波和 mip

- `BakeUV` 不按名字猜成 `uv1`：检查实际导出的 `TEXCOORD_n` 与加载后的 geometry attribute，在 manifest 中明确通道。
- 只执行一次坐标轴转换。glTF 已转换为 Y-up 时，禁止再次对模型重复转换；灯光、参考相机与模型根变换使用同一协议。
- 用非对称 UV 标记或已知局部区域验证纵向方向；外置贴图与 glTF UV 配合时显式确认 `flipY`，不能凭看起来相似判断。
- 原始像素纹理的放大/缩小均为 `NearestFilter`，关闭 mip 生成和混合，WebGPU anisotropy 设为 1；不为消除模糊而更改 sRGB 解码。
- 烘焙 atlas 使用线性/三线性、设备允许范围内最高 16× 各向异性；当前仅生成 0–2 级 alpha 加权 mip，避免透明空白使 chart 边缘变黑。两条采样路径分离，不自动给原始像素贴图套用 atlas 策略。
- 本轮有限 mip 不代表已确认完整 mip 链安全；继续检查远景运动和接缝，不自动重排 UV 或重烘。
- 不把 Blender 烘焙 margin 数字直接当作所有 mip 都安全的保证。若出现漏色，先调整运行时 LOD/采样并记录，不自动重排用户 UV。

## 5. 室内实时灯：以三排顶灯为主

### 5.1 Blender 实测快照

来源：当前打开的 `07_已烘焙贴图_降噪预览.blend`，单位比例 1，以下为世界坐标。最终导出时再次快照并随版本保存。

| 顶灯 | Blender 位置 | 标准转换后的 Three.js 位置 |
|---|---|---|
| 第 1 排 | `(-10.5, -5.5, 17.75)` | `(-10.5, 17.75, 5.5)` |
| 第 2 排 | `(0.5, -5.5, 17.75)` | `(0.5, 17.75, 5.5)` |
| 第 3 排 | `(11.5, -5.5, 17.75)` | `(11.5, 17.75, 5.5)` |

共同参数：

- 类型：矩形 Area Light，尺寸 **0.48 × 22.8 m**。
- 每排功率 **510 W**，Normalize 开启；灯对象缩放为 1。
- 线性 RGB **(0.90, 0.95, 1.00)**，Spread **90°**，Blender 阴影开启。
- Blender 朝向世界 −Z；标准轴转换 `(x, y, z) → (x, z, −y)` 后朝向 −Y，灯条长轴沿 Three.js Z 轴。
- 可见发光面约 **0.5 × 22.84 m**，相机分支自发光强度 **3.5**；实际照明由独立 Area Light 提供。

上表是未叠加额外房间根变换的结果；若模型移动、旋转或缩放，灯与参考相机必须同步。

### 5.2 首选基线：三盏矩形实时灯

- 用 3 盏 `RectAreaLight` 保留顶灯位置、长宽、方向、长轴与颜色，为未烘焙 PBR 物体提供实时直射。
- WebGPU 路径初始化 `RectAreaLightTexturesLib` / `RectAreaLightNode` 所需 LTC 数据。
- 明确限制：r187 `RectAreaLight` **没有阴影支持，也没有等价的 Blender Spread 参数**。不能把这个基线描述为完整复刻 Cycles 的灯光遮挡。
- Blender 的 510 W 不直接作为 Three.js `intensity`。用房间中不同横向位置、灯条两端及中部的灰色物件校准，记录转换/拟合依据。
- 冷白颜色按线性 RGB 设置，不误当成 sRGB 数值再次转换。
- 不自动导入并启用 GLB 灯光后再手动创建重复灯；实时灯只由一处配置生成。

### 5.3 阴影与遮挡的决策门槛

在梁下、柜体背面、桌下和可移动测试物体旁验证矩形灯漏照。GTAO 不能弥补镜头外遮挡、长距离灯影或完整动态投影。

若矩形灯的无阴影结果可接受，保留最低复杂度方案；若影响画面或目标可读性，则比较少量向下 `SpotLight` 的分段近似，限定锥角、衰减、距离与 shadow camera 范围。Spot 的点状直射与阴影并不等同于真实长条面积光，必须对照验收。

不能在原有完整 RectAreaLight 贡献上直接叠加同等强度 SpotLight。若混用，必须明确拆分两者承担的照明贡献并重新校准；不得仅用第二盏灯“补阴影”却重复计算直射。

已烘焙表面可以为未烘焙物体遮挡 Spot 光，但首版不承诺把动态阴影投射到 baked-appearance 材质上。若用户需要角色在烘焙地面/墙体上投影，应新增独立 shadow-receiver/合成设计并验收，不能靠 `receiveShadow = true` 宣称已实现。

### 5.4 环境补光与其他现有灯

未烘焙物体需要至少一条受控的间接/环境照明路径，否则背光面可能过黑，GTAO 也没有足够的间接分量可调制。

- 首版使用强度固定、经灰色物件校准的低频环境补光，仅作用于实时受光材质；这是近似，不宣称是精确 GI。
- 不直接叠加任意 HDR 环境、半球光和环境光；选择单一明确的基线，避免重复漫反射。
- 只有在单房间环境近似无法满足物体受光时，再评估少量离线探针；不把探针捕获或区域插值设为首版前置任务。
- 当前 Blender 另有暖色主 Spot **2040 W**、左右 Area 补光 **850/1020 W**、太阳与天空。这些都可能参与现有烘焙和未烘焙物体的参考外观；不宣称仅三排顶灯就能复现全部照明。
- 首版先建立顶灯基线，再根据物体对照结果决定其他灯的职责；不机械复制全部灯，也不为此重烘现有墙体。

## 6. GTAO 的接入规范

**GTAO 是屏幕空间遮蔽，不是光源、GI 或阴影贴图。** 本轮用于未烘焙物体的接触与凹处细节，不能乘暗整张最终画面来冒充正确的材质分工。

1. 墙体和未烘焙物体共同提供深度/法线，确保物体靠墙、贴地时有遮挡依据。
2. 使用 `builtinAOContext` 等已验证的间接光接入路径，使 AO 主要作用于实时材质的间接照明；不误调制其顶灯直接光。
3. 烘焙显示材质绕过重复 AO，不能因其不接收 AO 就把它从深度/法线预通道中移除。
4. 预通道保留 alphaTest、裁剪、双面语义以及蒙皮/顶点变形；透明/镂空物体逐类检查，不把整个包围平面当作实心遮挡。
5. 先在全分辨率建立参考，再比较半分辨率 GTAO + 去噪；只在移动边缘、细物体与接触细节通过后采用半分辨率优化。
6. 初始以单房间尺度设置小范围 AO，逐项测试半径、强度与去噪，不用大半径修补漏光或缺少间接光。
7. 检查屏幕边缘消失、细小物体 halo、相机运动闪烁和已有烘焙暗部；GTAO 关闭时基础照明仍必须成立。

预通道若无法正确为 unlit 烘焙材质输出几何法线，应修正预通道/节点输出，而不是重新让墙体受实时灯光。

## 7. 抗锯齿、显示变换和可选后处理

基线次序：

```text
深度/法线预通道 → GTAO → 空间去噪
                           ↓
HDR 场景渲染（实时物体间接光读取 AO；烘焙物体不重复读取）
  → 曝光 + 选定 tone mapping + 输出颜色转换（各执行一次）
  → 显示域 LUT（默认 identity，用户要求可调）
  → SMAA（默认首版抗锯齿）
  → 输出
```

- 使用 r187 `RenderPipeline` 和 TSL 节点，不按过期示例另建一套重复的颜色变换。
- 后处理场景 pass 的 MSAA 基线设为 0，避免未测量就与 SMAA 重复叠加。
- TRAA 属于第二阶段可选比较项，不阻塞首版。启用时在显示变换前处理 HDR，正确输出 velocity，并处理 resize、相机切换/跳变和资源切换的历史重置。
- 若采用 GTAO 时序滤波，应与 TRAA 方案一起验收；不得无条件叠加多套时序累积造成拖影。
- 显示变换按用户最新要求固定为 Reinhard，`toneMappingExposure = 1.2`；LUT 默认为 33³ 半浮点 identity，在显示 sRGB 域采样；不默认新增 Bloom、SSR、DOF 等效果。
- 用户已明确要求 AO/LUT 调试面板，复用现有 Tweakpane；除该范围外不扩展外观调参 GUI。

| `src/engine/systems/render/materials.js` | 创建烘焙显示与实时 PBR 材质，处理 UV、分类和 AO 策略 |
| `src/engine/systems/render/room-lights.js` | 顶灯、环境补光及经批准的 Spot/其他灯配置与生命周期 |
| `src/engine/systems/render/pipeline.js` | 深度/法线、GTAO、去噪、显示变换和 SMAA；后续按需 TRAA |
| `src/engine/systems/render/config.js` | 固定验收配置，显式记录显示、灯光与性能档位 |
| `tools/export_range_room.py` | 后续实现的 Blender 导出/清单检查工具，不负责重新展开或烘焙 |

接口方向：异步 `createRenderSystem({ engine, canvas, scene, camera, resources, config })` 完成 renderer 初始化；房间加载/绑定由 `loadRoom({ manifestUrl })` 完成，验证成功后再开放场景；返回系统提供 `update()`、`dispose()`，由外部注册到 engine 的 `render` 阶段，避免重复注册帧循环。scene/camera 由应用传入，不默认销毁整个场景。

现有 `ResourceManager` 已负责模板与共享 geometry/material/texture；继续通过 `instantiate()` 创建实例。渲染模块只释放自行创建的替换材质、纹理包装、灯光与后处理资源，不释放其他实例仍使用的共享贴图。

当前资源加载器只有普通纹理、HDR、GLTF 和 JSON 等类型；其 `hdr` 使用 `HDRLoader`，不能把它当成 EXR 支持。实现时为 `EXRLoader` 增加明确资源类型、类型注释和对应卸载分支。与普通纹理不同，atlas 不自动设置成环境贴图，也不使用普通颜色纹理的默认 sRGB 设置。

## 9. 分阶段实施与退出条件

### P0：固化导出清单和参考

- 确认房间导出范围、5 页实际编码、逐 primitive 分类和 UV 对应。
- 保存顶灯及其他参考灯快照，记录相同相机与显示设置。
- 导出房间 GLB、五张统一编码的降噪 atlas 和 manifest，不覆盖制作源文件。
- 输出模型统计和资源校验报告；选择并记录依赖/锁文件基线，不混用包管理器或自动删除锁文件。

退出条件：无缺页、无歧义绑定、无遗漏分类；模型、贴图和坐标版本匹配。若发现资产问题，报告具体接收面，不自动重做 UV/烘焙。

### P1：最小房间渲染与烘焙外观对齐

- 建立独立 render system，替换环面纽结测试渲染入口，保留既有 engine 生命周期。
- 只显示正式房间资源，绑定 baked-appearance 材质；GTAO、LUT 与额外实时照明关闭。
- 验证五页采样、方向、贴墙近景、接缝和 HDR/显示变换；无实时照明时烘焙墙体仍正常显示。

退出条件：同机位下烘焙外观与 Blender 参考的主要颜色、亮暗和纹理位置一致；剩余显示变换差异有独立记录，不通过改灯功率掩盖 atlas 错误。

### P2：未烘焙物体与顶灯校准

- 还原未烘焙物体的原始材质、透明裁剪和采样风格。
- 创建三排矩形灯与单一受控环境补光；用多个位置和朝向的灰色测试物体校准。
- 对比三排灯下、两排灯之间、灯条两端、物体背光侧与大型遮挡物背面。
- 根据第 5.3 节决定保留 RectAreaLight，或进入有限 Spot 近似测试；必要时确认其他 Blender 补光的角色。

退出条件：未烘焙物体受光协调，烘焙墙体不因运行时灯开关而重复增亮；无阴影的局限已通过画面验收或有明确替代方案。

### P3：GTAO 与 SMAA

- 接入覆盖两类几何的深度/法线预通道，AO 只按规则作用于实时材质。
- 在物体贴墙、贴地、细网格/镂空、相机边缘与移动过程中比较 AO 开/关。
- 接入 SMAA；比较 GTAO 分辨率和去噪档位，固定首版配置。

退出条件：接触细节改善但无烘焙墙角重复压黑；运动时无明显 halo、闪烁或遮挡断层；开启 AO 不依靠压暗直接光掩盖错误。

### P4：性能与可选增强

- 实测显示尺寸、DPR、实际适配器、纹理格式、GPU/CPU 时间与显存估算。
- 在单房间范围评估 draw calls、atlas mip、阴影灯数量和预通道开销。
- 只有收益明确时才加入 TRAA、LUT、少量探针或反射增强；每项保留独立开关对照和成本记录。

退出条件：达到用户明确的目标设备/分辨率/帧率预算。未明确目标前只报告实测，不宣称竞技高帧率已达标。

## 10. 验收清单与性能记录

视觉参考至少包括：房间总体、各 atlas 的近景表面、顶灯下与灯间物体、遮挡物背面、贴墙/贴地接触，以及原地转动/横向移动/改变高度的连续画面。使用相同固定曝光；禁止自动曝光掩盖差异。

功能检查：

- [ ] 只加载当前练枪房，不依赖旧整图或旧探针坐标偏移。
- [ ] 五页绑定完整，UV/朝向正确，运行时只加载降噪版。
- [ ] 烘焙图未重复乘底色、重复受光、重复色彩转换或重复叠 AO。
- [ ] 未烘焙物体有基础受光，GTAO 关闭时仍有合理外观。
- [ ] 灯具可见自发光和实际照明分离；灯光数据没有被重复导入。
- [ ] AO 遮挡几何、接收对象、镂空与变形物体正确。
- [ ] 矩形灯阴影限制及可能的 Spot 方案有显式验收记录。
- [ ] resize、销毁与房间重新加载后无监听器、共享资源误释放或持续显存增长。
- [ ] 实现阶段使用选定包管理器构建成功，浏览器无未处理错误；诊断能定位页 ID 和接收面。

性能记录至少包含：下载大小、加载/解码/首次编译耗时、几何与 draw calls、atlas GPU 格式和 mip、GTAO/去噪/AA 各 pass 开销、阴影开销、CPU/GPU 帧时间及 P95/P99。GPU 时间戳不可用时明确标记，不能把 CPU 提交时间标成 GPU 时间。

五张 2048² atlas 的纹理内存量级：若实际采用 RGBA16F，为 **160 MiB（基础级）/ 约 213.3 MiB（完整 mip）**，不含其他纹理与渲染目标。若变成 RGBA32F 则约翻倍；EXR 磁盘压缩大小不代表 GPU 显存。以实际上传格式为准，首版不默认同时驻留五张原图与五张降噪图。

测试截图、浏览器配置、缓存与临时报告统一放在 `D:\opencode-temp` 下；正式运行资源留在项目 `public/`，制作源文件保留原位置。

## 11. 本轮非目标与变更边界

- 不重新展开现有墙体 UV，不重烘、不修改用户已经确认的静态外观。
- 不恢复整张地图、多房间 streaming、室外太阳 CSM 或连续昼夜系统。
- 不接入 VXGI、运行时 LightMapper、全图 LightProbeGrid 捕获或旧顶点 GI 实验。
- 不把多区域 SH 探针、clustered lighting、LUT 或复杂反射设为首版前置项。
- 不自动承诺 baked-appearance 表面接收动态阴影、枪口闪光或任意新增灯光；本轮仅为已要求的走廊三盏点光提供局部叠加路径。
- GUI 限于用户追加要求的 AO/LUT 面板，不扩展玩法、碰撞或角色控制系统作为本任务的附带工作。
- 文档完成后才进入实施；任何需要改变源材质、UV、烘焙结果或灯光艺术布局的修复，先说明影响并征得确认。

**最终路线：保留现有五页烘焙成果 → 明确导出与绑定 → 还原烘焙墙体 → 顶灯照亮未烘焙物体 → GTAO 与抗锯齿 → 性能验收。**
