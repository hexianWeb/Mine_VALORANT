## 3. P2.1 目标与非目标

### 目标

- 玩家以第一人称在练枪房内行走：重力、跑/静步/下蹲、跳跃、贴墙滑动、自动上台阶（半砖、楼梯）。
- 场景碰撞来自 Blender 中单独制作的简化碰撞盒层，导出为 JSON。
- Pointer Lock 鼠标视角，灵敏度与无畏契约数值一致。
- 室外无限地形可行走（运行时地面碰撞盒）；出生点；踩穿地板或掉出地形（低于 `killY`）自动回到出生点。
- 保留飞行模式作为 noclip 调试，V 键切换。
- 碰撞盒线框可视化，默认关闭。

### 非目标

- 动态刚体（弹壳、可击飞道具、布偶）；不引入 Rapier 等物理库。
- 射击射线、穿透、Bot 碰撞（P2.3/P2.4）。
- 武器模型、脚步声、地面材质字段（P2.2）。
- 斜坡、旋转碰撞体、三角网格碰撞。
- 宽相加速结构（先暴力遍历，见 4.2）。

## 4. 技术方案

### 4.1 方案选择

采用自写运动学 AABB 控制器，按轴分离解算（Y → X → Z），即 Minecraft 原版同源做法。

- 碰撞层全部是轴对齐盒子，楼梯做成台阶盒，不需要斜坡/三角形碰撞。
- 无外部依赖、结果确定、纯逻辑可在 Node 中测试。
- 否决：胶囊体 collide-and-slide（成本约 2–3 倍，方块场景收益小）；Rapier KinematicCharacterController（约 1.5 MB WASM + 完整刚体世界，只为一个玩家属于过度设计）。将来需要动态刚体时可复用本碰撞层数据。

### 4.2 宽相

碰撞盒全静止、移动体只有玩家一个。按约 1000 个盒子估算：60Hz × 3 轴 × 1000 次比较 ≈ 18 万次/秒，JS 中为亚毫秒级。因此先暴力遍历，宽相隐藏在 `queryAABB(box)` 接口后；实测成为瓶颈时再在接口内部换成均匀网格或 Sort and Sweep，调用方不变。

### 4.3 模块划分

依赖方向保持 `world → engine`。

| 文件 | 职责 | 依赖 |
|---|---|---|
| `src/engine/systems/input/index.js` | Pointer Lock 与键鼠事件；每帧输出意图 `{ moveX, moveZ, walk, crouch, jump, lookDX, lookDY }`；监听器经 `Disposer` 释放 | DOM |
| `src/engine/systems/physics/collision-world.js` | 静态 AABB 列表（碰撞层 JSON + 运行时地面盒）；`queryAABB(box)` 返回相交盒子（暴力遍历） | 无 |
| `src/engine/systems/physics/character-controller.js` | 纯函数 `moveAABB(world, box, displacement, { stepHeight, snapDown })`，返回 `{ grounded, hitX, hitY, hitZ }`；不依赖 three/DOM | `collision-world` |
| `src/engine/systems/physics/index.js` | 物理系统；`fixedUpdate` 中以 `time.fixedDelta` 推进玩家 | 上述两者 |
| `src/world/player.js` | 玩家对象（transform、移动状态、碰撞盒组件）；意图 → 期望速度；出生点/重置；相机跟随；移动参数配置 | `engine` |
| `src/world/collision-debug.js` | 碰撞盒 `LineSegments` 线框，可开关，`dispose()` 释放几何 | three |
| `tools/export_collision.py` | 只读导出 `COLLISION_PracticeRoom` 与 `Spawn` | Blender |

### 4.4 每帧数据流

1. input：读取设备，写意图对象。
2. gameplay：鼠标位移直接应用到 yaw/pitch（每帧更新，不等固定步，避免视角延迟）；pitch 限制在 ±89°。
3. physics：`fixedUpdate` 执行 `time.fixedSteps` 次；每步玩家由意图计算速度并调用 `moveAABB`，同时记录上一步与当前位置。
4. animation：相机位置 = 两步位置按 `time.alpha` 插值 + 眼高（下蹲时眼高平滑过渡）。
5. render：不变。

### 4.5 模式切换

- 检查面板新增「玩家」模式；碰撞层加载完成后默认进入玩家模式。
- V 键在玩家模式与飞行模式（noclip，复用现有 `FlyController`）之间切换。
- 切回玩家模式：把玩家放到当前相机正下方的地面；若该位置与碰撞盒重叠，则回到出生点。
- Esc 退出 Pointer Lock；再次点击画面重新锁定。
- 碰撞层加载失败时停留在飞行模式，并在控制台报错，不影响渲染。

## 5. 碰撞层数据

### 5.1 文件格式

路径：`public/collision/range-room.json`。坐标为运行时世界坐标（Y 向上，米）。

```json
{
  "schemaVersion": 1,
  "id": "range-room-collision-v1",
  "units": "metres",
  "up": "Y",
  "spawn": { "position": [0, 0, 0], "yawDeg": 0 },
  "boxes": [
    { "name": "Wall_N_01", "group": "Wall", "min": [-8, 0, -12], "max": [8, 4, -11.5] }
  ]
}
```

- `spawn.position` 为玩家碰撞盒底面中心。
- 地面与 `killY` 不写入文件，运行时由 `world.ground.snapshot()` 派生，与超平坦地面画面同源：
  - 地面碰撞盒：水平范围 = `outer`（房间中心 ±8192 m，含房间正下方），顶面 = `height`（模型最低点 − 0.01 m，当前 7.865 m，与模型底部齐平），厚 1 m。
  - `killY` = `height` − 10 m，兜底穿过地面碰撞盒的情况。
- 踩穿地板重置：名称含 `_Floor_` 的盒子为地板盒（当前 50 个，顶面 7.5–9.0 m）。每个固定步检查：玩家脚底低于某地板盒底面且水平投影与其重叠，即判定在地板下方，回到出生点。正常行走无法到达该状态。

### 5.2 Blender 约定

- 碰撞体放在 `COLLISION_PracticeRoom` 的 `COLLISION_*` 子集合中（子集合名写入盒子的 `group`），每个对象为立方体；旋转只允许 0° 或 90° 的倍数，导出时不符合直接报错。
- 楼梯每级一个盒子，单级高度不超过 0.5 m。
- 名为 `Spawn` 的 Empty 标记出生点位置（脚底）与朝向（局部 -Y 为前方）；缺失时用场景相机水平位置落到下方碰撞盒顶面。
- `tools/export_collision.py` 只读不改场景，可在当前 Blender（MCP）或后台命令行运行，坐标按 manifest 的 `x,z,-y` 规则转换。导出结果与说明见 [碰撞层 v1](../../physics/collision-layer.md)。

### 5.3 初稿生成（Blender MCP）

由 AI 生成初稿、用户手工修整：

1. 渲染网格按 0.125 m 精度体素化。
2. 贪心合并为尽量少的大盒子。
3. 过滤薄小装饰物（灯、挂件等），写入 `Collision` 集合。
4. 交付时附易错清单（玻璃板、栅栏、楼梯、栏杆等），供用户优先检查。

### 5.4 校验（纳入 `npm test`）

- 每个盒子 `min < max`（三轴），无退化盒。
- 所有盒子位于房间包围盒外扩 2 m 范围内。
- 出生点处的站立碰撞盒不与任何盒子重叠。
- `schemaVersion` 与必需字段存在。

## 6. 移动参数与解算

参数集中在 `src/world/player.js` 顶部的冻结配置对象，直接改代码，不做调参面板。速度为参照无畏契约公开数据的初始值，需对照实机手感校准。

| 参数 | 初始值 | 说明 |
|---|---|---|
| 站立碰撞盒 | 宽 0.6 × 高 1.8 m，眼高 1.62 m | MC 尺寸，可通过 1 格宽通道 |
| 下蹲碰撞盒 | 高 1.5 m，眼高 1.27 m | 头顶有遮挡时不能站起 |
| 跑 / 静步 / 下蹲速度 | 6.75 / 3.8 / 3.4 m/s | 静步 Shift，下蹲 C（Ctrl 与浏览器 Ctrl+W 冲突） |
| 地面加/减速 | 约 0.08 s 到全速或停下 | 反向急停干脆 |
| 空中控制 | 地面加速度的 15% | 无连跳加速 |
| 重力 / 跳跃高度 | 20 m/s² / 1.1 m | 起跳速度约 6.63 m/s，可跳上一整格 |
| 下落速度上限 | 50 m/s | |
| 自动上台阶 | 0.55 m | 仅着地时；半砖/楼梯直接走上，整格需跳 |
| 鼠标灵敏度 | 每计数 0.07° × 灵敏度 | 与无畏契约灵敏度数值一致 |

解算要点：

- 按轴顺序：Y → X → Z；某轴被挡住时该轴位移截断到最近盒面，速度清零，形成贴墙滑动。
- 自动上台阶：着地且水平被挡时，抬高至多 0.55 m 重试水平移动，再向下落回；抬高路径被挡则放弃。
- 下楼梯贴地：上一步着地且本步未起跳时，向下吸附至多 0.55 m。
- 防穿透：查询用整段位移扫过的包围盒而非终点；50 m/s 下落（每步 0.83 m）也不穿薄板。
- Pointer Lock 请求 `unadjustedMovement: true` 绕过系统鼠标加速，不支持时回退普通模式。

## 7. 调试与检查接口

- 左下角检查面板新增「碰撞线框」按钮（调试开关，非外观调参）。
- V 键切换 noclip。
- `__RANGE_ROOM__.snapshot()` 新增 `player`：位置、速度、是否着地、是否下蹲、模式、碰撞盒数量、最近物理步耗时。

## 8. 验收标准

1. 单元测试（`node --test`）覆盖：落地、贴墙滑动、墙角不卡住、上 0.5 m 台阶、被 1.0 m 方块挡住、头顶遮挡不能站起、50 m/s 下落不穿透、下楼梯贴地、脚底低于地板盒底面时触发重置、站在地面碰撞盒上不误触发重置。
2. 碰撞层校验通过（第 5.4 节）。
3. 浏览器脚本 `tools/check-player-browser.mjs`：模拟输入撞墙、上楼梯、掉出地图，断言位置并截图。
4. 人工验收：房间内完整走一圈不被卡住；楼梯正常上下；无法穿墙离开房间；可走出房间在室外地面行走；noclip 钻到地板下切回玩家模式即回到出生点；反向急停手感可接受。
5. 性能：单个物理步 < 0.2 ms。

## 9. 风险

- 体素化初稿在玻璃板、栅栏、栏杆处可能过厚或缺失，需人工修整；以易错清单降低遗漏。
- 速度/跳跃参数为初始值，手感需迭代；参数集中一处便于调整。
- 碰撞层与渲染模型分离，模型改动后碰撞层可能过期；以第 5.4 节包围盒校验发现明显偏差。
