# 第一人称武器材质与质感优化路线图

> 状态：后续优化思路，尚未实施。本文不是现有功能清单，也不代表已确定的最终美术参数。
>
> 推荐方向：**先做分区 PBR 材质和室内反射，再补接触遮蔽与边缘细节。**

## 1. 目标与边界

目标是让武器与当前 Minecraft／低模场景属于同一个画面，同时具备可信的材料层次，而不是把武器单独改成摄影级写实资产。

期望效果：

- 枪壳、裸露金属、握把和角色手臂具有不同的表面响应。
- 枪身的反光能够解释为来自房间顶灯、墙面和地面，而不是始终映出室外天空。
- 亮处不过曝，暗处保留结构；移动和转身时受光自然变化。
- 待机、ADS、检视和换弹中都保持一致，不仅在某一张截图里好看。

实施边界：

- 不通过提高全局曝光、修改全局 LUT 或强补光掩盖武器问题。
- 不改变枪械玩法、动作时钟、持枪位置或 ADS 投影。
- 不默认重绘现有皮肤；需要新增贴图或修改模型时，单独确认范围。
- 角色手臂遵守[手臂 UV 与贴图规范](arm-uv-contract.md)，不混入武器皮肤包。
- 保留视模的独立深度、HDR 合成与世界 AO 隔离，不重新引入贴墙裁切。

## 2. 当前基础与主要瓶颈

当前已具备共享世界灯光、LightProbeGrid 和天空环境的独立视模渲染，材质参数按 weapon / scope / armsLeft / armsRight 角色配置。现行实现以[武器发布与动画播放](animation-and-assets.md)为准。

后续主要瓶颈：

1. **材质分区不足**：同一枪身材质主要依赖颜色贴图与统一参数，难以表现涂装、金属和橡胶的区别。
2. **室内反射来源不足**：已有环境反射主要来自天空；漫反射探针不能替代室内镜面反射。
3. **接触与边缘信息不足**：握枪位置、弹匣接口和凹槽缺少适量遮蔽，硬边也未必能接住高光。
4. **调参方式不足**：已有暗部补光控制，但进一步校准仍需要材质对照、实时倍率和固定测试机位。

## 3. 优先级

| 优先级 | 工作项 | 主要收益 | 控制范围 |
| --- | --- | --- | --- |
| P0 | 固定对照机位与评价标准 | 避免只针对一张截图反复调参 | 不改资产，先记录基线 |
| P1 | 分区 PBR 材质 | 从根本上区分不同材料 | 先选一把枪、一个皮肤做小样 |
| P1 | 静态室内反射 | 让高光和反射与所处空间一致 | 先覆盖练枪房，再考虑走廊过渡 |
| P2 | 轻量接触遮蔽 | 加强部件嵌合与握持关系 | 不直接复用世界 AO |
| P2 | 适量倒角／法线细节 | 改善边缘高光与结构可读性 | 保留低模轮廓和像素风 |
| P3 | 视模自阴影 | 补充复杂姿态下的体积关系 | 仅在前述手段仍不足时评估 |

## 4. 方案一：分区 PBR 材质

### 4.1 按真实材料划分，而不是按贴图亮暗猜测

| 区域 | 目标响应 | 调整原则 |
| --- | --- | --- |
| 涂装外壳 | 柔和、较宽的高光，图案清晰 | 普通不透明涂层通常按非金属处理，不因底下是金属就整面设为金属 |
| 裸露金属 | 明确的环境反射 | 金属度接近金属端，粗糙度按表面加工和风格校准 |
| 塑料握把 | 较弱反光、偏粗糙 | 保持非金属，不与枪壳共用一种反光强度 |
| 橡胶部件 | 高粗糙度、低反射存在感 | 避免黑色部件出现油亮或镀铬效果 |
| 袖子／手套 | 哑光，保留像素色块 | 独立校准，不随武器换肤改变 |

**金属度不是通用的“质感增强”滑条。** 提高金属度会改变漫反射与镜面反射的能量分配；反射环境不足时，材质反而可能变黑。应先明确材料，再校准数值。

### 4.2 逐步补充材质贴图

优先增加粗糙度与金属度遮罩；法线和 AO 在确有结构需要时再增加。

| 数据 | 色彩空间 | 用途 |
| --- | --- | --- |
| Albedo／基础颜色 | sRGB | 保留皮肤颜色和图案 |
| Roughness／粗糙度 | 非颜色数据，不做 sRGB 解码 | 控制高光宽度与反射清晰度 |
| Metalness／金属度 | 非颜色数据 | 区分金属与非金属区域 |
| Normal／法线 | 非颜色数据 | 补充边缘、凹槽等局部结构 |
| AO／环境遮蔽 | 非颜色数据 | 补充稳定的局部间接光遮蔽 |

可评估使用 ORM 打包：R 为 AO、G 为粗糙度、B 为金属度。是否打包应根据加载与采样实现确定，不在未验证前规定最终资源格式。

注意事项：

- 当前皮肤加载契约需要扩展后才能支持这些可选输入；不能只放入 PNG 就认为运行时会使用。
- 缺少新增贴图的旧皮肤应继续使用角色级参数，保持向后兼容。
- 遮罩依据明确的材质区域制作，不用 Albedo 的明暗直接推断金属度或凹凸。
- 不同皮肤可具有不同涂层；UV 兼容不代表一定能共用全部材质贴图。
- 基础颜色保持像素锐度；材质遮罩与 UV 边界对齐，避免滤波串色和高频法线闪烁。
- 法线贴图必须验证切线空间、左右镜像 UV、法线方向和 V 翻转约定。

## 5. 方案二：静态室内反射

### 5.1 与现有探针分工

现有 LightProbeGrid 用于漫反射间接光；新增室内反射用于镜面部分。两者应互补，而不是把同一份间接光重复叠加。

建议先在练枪房制作一个静态反射小样：

1. 从静态房间捕获包含顶灯、墙面和地面的线性 HDR 环境。
2. 排除第一人称武器、角色、移动道具和调试辅助物，避免自我反射或过期动态物体。
3. 生成适配粗糙度的预过滤反射，按材质粗糙度取样。
4. 仅替换或受控混合镜面环境，不重复增加现有探针漫反射。

捕获结果不应提前烘入曝光、色调映射或显示 LUT，否则会与最终管线重复处理。

### 5.2 空间覆盖与性能

- 先完成房间单探针，再评估走廊独立探针以及交界处的空间混合。
- 若近距离反射的空间错位明显，再评估盒投影校正；不把它作为第一步的前置条件。
- 优先预计算或在必要的场景变化后更新，不默认每帧捕获。
- 实测捕获分辨率、显存和 GPU 成本，不仅凭单帧画面决定质量档位。
- 保留天空反射作为室外区域与无有效室内探针区域的回退。

## 6. 方案三：接触遮蔽与边缘细节

### 6.1 先补接触关系

重点观察握把与手的接触处、弹匣接口、机匣凹槽及部件缝隙。

- 对稳定的枪体结构，优先评估轻量 cavity／烘焙 AO。
- 对随动画变化的手与枪接触关系，再评估视模专用的小尺度屏幕空间遮蔽。
- 半径按武器的厘米级结构标定，不能直接沿用房间 AO 的米级参数。
- 遮蔽作用于对应的间接光，不简单乘黑最终画面；检查是否与贴图已有阴影重复。
- 接触处应更清楚，但不能出现大块脏黑、黑色光晕或掏枪时明显闪动。

### 6.2 再补边缘高光

- 仅对需要承接高光的边缘增加适量倒角，或将细节烘焙到法线。
- 保留原有硬朗轮廓，不全局磨圆、细分或添加写实微噪声。
- 划痕、磨损和露底金属应具有材料依据，不把随机噪声当作质感。
- 修改拓扑、UV 或模型时，重新核对兼容签名并发布新版本，不能伪装成只换贴图。

自阴影放在后续可选项中：只有上述措施仍无法表达体积关系时，才评估独立、稳定的视模阴影方案，并防止世界墙面遮挡破坏视模可读性。

## 7. 方案四：稳定的材质校准流程

### 7.1 实时调试

建议在现有「武器 · 场景光照」基础上增加：

- 按角色调整粗糙度／金属度参数或贴图倍率。
- 环境镜面强度、弱补光及各项效果的独立开关。
- 单项对照、恢复默认值和记录候选配置。

参数应更新实例材质或 uniform，避免每次拖动都重建模型、播放器或整条渲染管线。实时效果与保存为项目默认值分开处理，避免无意覆盖正在进行的美术调参。

### 7.2 对照矩阵

| 维度 | 最少覆盖 |
| --- | --- |
| 光照位置 | 顶灯下、室内暗部、走廊／门口、室外 |
| 视角 | 正常持枪、转向不同灯光方向、上下观察 |
| 动作 | 待机、ADS、检视、换弹、射击 |
| 皮肤 | 深色、浅色与高对比图案，避免只针对一款校准 |
| 运行状态 | 切枪、换肤、Editor 返回、暂停／恢复、窗口缩放 |

固定相机、姿态、曝光、LUT、分辨率和效果开关，保存修改前后截图。必要时先用中性调色排查，再回到正式显示配置验收；不要为了枪身改变整个场景的视觉基准。

## 8. 推荐实施节奏

### 第一轮：确认材料方向

- [ ] 记录当前画面和 GPU 基线。
- [ ] 选择一把枪、一个皮肤，标注涂装／金属／握把区域。
- [ ] 做最小的粗糙度、金属度遮罩与加载小样。
- [ ] 用相同姿态比较统一参数与分区材质，确认不是单纯变亮。

### 第二轮：确认室内空间感

- [ ] 加入房间静态镜面反射小样。
- [ ] 比较天空反射、室内反射及各自关闭的结果。
- [ ] 检查顶灯高光、暗部层次、转身响应和室内外回退。

### 第三轮：推广与精修

- [ ] 推广到另一把枪和其他皮肤，保留旧皮肤回退。
- [ ] 补足实时调试面板，减少文件修改／热更新对校准的干扰。
- [ ] 根据实际缺口选择 AO、倒角或法线，而不是全部同时加入。
- [ ] 再决定是否值得增加自阴影或更复杂的反射校正。

**每轮只改变少量因素，先截图确认风格，再进入下一轮。** 现有双枪的材质小样不应与其余枪型的完整发布绑定；涉及重新导出模型时，仍需满足相应源资产与元数据要求。

## 9. 工程与验收要求

可能涉及的代码入口：

- `src/game/weapons/assets/weapon-materials.js`：材质角色与参数配置。
- `src/game/weapons/assets/weapon-assets.js`：可选贴图加载、校验、换肤和资源归属。
- `src/engine/runtime/function/render/passes/viewmodel-pass.js`：视模光照、独立深度与效果隔离。
- `src/game/range-room/lighting/`：室内反射与现有探针照明的分工。
- `src/engine/editor/panels/render-panel.js`：实时校准与对照控件。
- `tools/weapons/`：新增材质资源的发布、版本与完整性验证。

工程边界：

- 武器皮肤不能覆盖共享角色手臂；遵守已有 UV、镜像方向与纹理所有权契约。
- 换肤保持原子性，不能出现颜色已换、其他材质贴图仍属于旧皮肤的中间状态。
- 不覆盖已发布资产版本，不绕过 manifest、哈希及兼容性校验。
- 制作源的修改须先明确范围并备份；截图、捕获、候选资源和临时报告放在 `D:/opencode-temp/opencode/`。
- 每项新增效果单独计时，检查反复切枪／换肤后的纹理、材质和渲染目标是否增长。

基础回归命令（浏览器检查需要先运行开发服务器）：

```powershell
npm test
npm run build
node tools/check-weapon-lighting-browser.mjs http://localhost:5173/
node tools/check-weapon-gameplay-browser.mjs http://localhost:5173/
node tools/check-pipeline-browser.mjs http://localhost:5173/
```

上述检查是现有基线，不代表已经覆盖未来新增的 PBR 遮罩、室内反射和视模遮蔽；实施时需要为新增功能补充针对性验证。验收应同时满足：**材料层次清楚、场景风格一致、动画与玩法不退化、性能及资源生命周期可控。**
